Let an agent run overnight. In the morning you open the PR it submitted — a few hundred lines of changes, neatly organized. You're about to review when a thought stops you cold: **on these few hundred lines, you are the first human who has ever actually looked at them.**

The author never saw them. The committer never saw them. The tests were run by the same thing that wrote the code.

"Who reviews AI-written code?" has gone from a joke to an engineering problem. And in a single week this September, four head platforms all turned in their homework — each with a different answer. This post is a field survey of those answers: four platforms, four review architectures, and what they reveal about where the industry is heading.

*This is Part 1 of the "Agent Reviews Agent" series. Part 2 tears open the source code of Codex Guardian to see what a production AI reviewer actually looks like inside.*

## The premise of code review just collapsed

Code review has run for twenty years on an implicit premise: **the author understands the code, and you're checking her work.** When you have a question during review, you walk two desks over and ask. The tradeoffs she made, the pits she stepped in — they live in her head. Review is, at bottom, a reconciliation between two people about "why it was written this way."

An agent's PR rips that premise out. There is no author's brain to reconcile with — the code was generated by a model, the commit message was written by a model, the tests were run by a model. One developer described reviewing an agent's PR as feeling like becoming "the first human to see this code" — a line quoted repeatedly this year because it lands on something real: **the reviewer is no longer checking someone's work; the reviewer is retro-fitting an understanding of the whole system.**

This is not a niche scenario. O'Reilly Radar published a long feature on agentic code review mid-year, citing data that GitHub's Copilot review has run more than 60 million times — 10x growth in a year — and that one in five reviews on the platform now involves an agent. The direction is clear: **the volume of machine-reviewed code is overtaking human-reviewed code.**

The only question left: how do you review in a way you can trust?

## Codex: install an internal affairs department

OpenAI's Codex shipped 342 commits this week and released rust-v0.154.0. Unremarkable numbers — except they contain an unusually coherent piece of engineering: **eight consecutive commits** assembling a review system called **Guardian**, piece by piece, converging into a reviewer extension.

Look at what those eight commits covered, then what it means.

**Approvals need routing.** Guardian approval routing — after a review finds a problem, who does the approval ticket go to, and by what rules? Institution first, execution second. A review conclusion without routing is just a line in a chat log that says "looks fine."

**Conclusions need a formal exit.** Review reporting turns review results into formal artifacts. It looks mundane, but it upgrades "reviewing" from a conversational act into a process step with outputs — and only outputs can be consumed downstream, archived, and audited.

**Denials need bookkeeping.** Denial accounting — every rejected change goes in a ledger: which review rejected it, why, and what happened next. The thing a review system should fear is not "let a bad change through" but "rejection itself becoming a black box." Without a ledger you can't answer "how many problems did review actually catch?"

**Reviewers need life and death.** Reviewer lifecycle — reviewers must be managed: when they come on duty, when they rotate, when they retire. A reviewer who never rotates is a slowly ossifying single point of failure.

**Assessments need to be machine-readable.** Assessment parsing structures the review output. Humans read conclusions in prose; systems consume them in formats. This is the prerequisite for wiring review into automated pipelines.

**Reviewers glitch, so you need a kill switch.** Circuit breaker — if the review stage itself goes wrong (deadloop rejections, or mindless approvals), the system must be able to cut it off rather than let the whole pipeline go mad with it.

Read the six together and you see that Codex is not "adding an AI review feature." It's designing an **institution**: routing, reporting, bookkeeping, rotation, parsing, circuit-breaking — every one of them organizational design language, not model capability language.

And one architectural decision is easy to miss: none of this is hardcoded into the agent loop. It's an **extension**. Review is pluggable — independently evolvable, independently fail-able, independently replaceable. Compare that to platforms that hardcode "self-check steps" into prompts, and you're looking at a generational gap. All of Guardian's week-ten action happened inside the extension; the main loop didn't change by a line.

## OpenClaw: let the agent fix its own PRs

The same story has a second protagonist with a bigger part.

OpenClaw shipped 4,208 commits this week and two releases (v2026.9.4, v2026.6.35). The theme was systematic convergence on stability and resource usage — sessions reusing compiled transcript metadata queries, reminder maintenance pulling less data, participant records writing less to the database, cron skipping availability checks during session-pruning idle windows. A textbook maturity-phase profile: polishing, not feature-stacking.

But the more historic line is this: the issue "Autofix: add PR review autofix pipeline + Windows daemon" was **closed after accumulating 2,500 comments** — OpenClaw really is running a PR auto-fix pipeline, **using its own agent to fix PRs in its own repository**.

Note the progression: Codex's Guardian stops at "review"; OpenClaw's autofix goes all the way to "fix." Agent output has a problem? Don't wait for a human — dispatch another agent to fix it directly on the PR. Eating your own dog food, all the way into the CI pipeline.

An instructive contrast sits in the same repo: issue #80396 (a warning when `MEDIA:` tokens get skipped inside fenced code blocks) has 704 comments and remains open. The boundary of what automation covers is sharply visible — the pipeline fixes formatting and regressions, not product judgments that need a human to own.

## HiClaw: human review, down to team granularity

Interestingly, the platforms pushing review institutions forward this week weren't all in the "AI reviews AI" camp. HiClaw walks the human-review road, and keeps digging deeper.

Of its 13 commits this week, the heaviest is `team-scoped worker tool approval endpoints for L2 humans` (#1216) — the human approval channel sunk down to team scope. Translation: *which team's* worker tool calls need a human signature is now cut at the team level. "Who signs off" is no longer a global switch; it's a formal dimension of the permission system.

Two companion commits matter just as much. `mermaid workflow rendering + task-level inspection API` (#1230) renders workflows as diagrams with per-task inspection — **humans can only review what they can see**. And `persist durable task continuation state` (#1183) persists continuation state, so when review interrupts a task it can resume from a checkpoint — review can afford to actually say "stop." Add permission levels granted to human members joining Matrix rooms, and a read-only skill catalog endpoint, and HiClaw's "human-machine hybrid team" positioning keeps cashing out in code.

## Hermes and the guardrail floor: institutions plus hard limits

**Hermes-Agent takes the "institutional review" road.** 2,401 commits this week, releases v0.21.2 and v0.21.3 within a fortnight. It wrote a whole suite of **invariant tests** for MoA (Mixture-of-Agents) and approval: non-finite temperature is always rejected, fanout overflow must be tolerated, and the sharpest one — **in unattended mode, the pattern-key allowlist must hold.**

In plain language: when nobody's watching, what the agent may do can't rely on its own good judgment — it needs hard allowlist constraints. And this isn't a rule written in a doc; it's an assertion running in the test suite. Violate it, and the build goes red.

Hermes also has a hot open issue that belongs in this context: "fix(delegation): separate lifecycle from task outcome" (#68499, 173 comments). For delegated tasks, "can I manage the process" and "is the result correct" are being split into separately-managed things — itself a refinement of review boundaries. Lifecycle management is one mechanism; result verification is another. Conflate them and you manage both poorly.

One floor below the institutions, a layer of **hard guardrails** landed this week in a remarkable convergence:

- PraisonAI fixed an SSRF bypass via octal-encoded loopback addresses (#4966, 292 comments), shipping v4.7.7 and v4.7.8 within days;
- RocketRide-Server, the same week, blocked SSRF destinations in `tool_http_request` — the same attack surface, fixed in parallel;
- ZeroClaw unified pairing-code handling into a single policy with hardened defaults, forced all outbound HTTP through the runtime proxy, and sanitized public health error messages (v0.8.5).

Once an agent can hit arbitrary URLs, SSRF becomes a shared attack surface. Review is a soft constraint; this layer is the floor. Soft constraints leak. Floors must not.

## Four architectures, side by side

Here are the same five questions asked of each platform:

**🛡️ Codex Guardian — AI reviews, institutions bind it.** Who reviews: AI (reviewer extension). What: agent outputs and approval flow. Vehicle: pluggable extension, main loop untouched. Backstop: circuit breaker + reviewer rotation. This week: 8 consecutive commits, 342 total.

**🐶 OpenClaw Autofix — AI reviews, and fixes.** Who reviews: AI (its own agent). What: PRs in its own repo. Vehicle: CI pipeline. Backstop: closed loop — found a problem, dispatch an agent to fix it. This week: the 2,500-comment autofix issue officially closed.

**👁️ HiClaw — humans review, at team granularity.** Who reviews: humans (L2). What: team-scoped worker tool calls. Vehicle: scoped approval endpoints. Backstop: permission granularity + durable task continuation (review dares to interrupt). This week: #1216/#1230 landed.

**🧱 Hermes — institutions review, assertions enforce.** Who reviews: the institution (pattern-key allowlist + invariant tests). What: MoA/approval parameters and run modes. Vehicle: a mandatory test suite — violations go red. Backstop: unattended-mode allowlist as hard constraint. This week: 2,401 commits, v0.21.3.

These four arrangements aren't a pick-one menu. They stack into defense in depth: **the floor is guardrails, the middle is institutional constraints, above that humans sign off, and at the top AI watches AI.** Each layer assumes the one below it will fail.

## The death spot of AI-reviewing-AI: correlated blind spots

By now you might ask: isn't AI reviewing AI just a self-licking ice cream cone?

That's the sharpest challenge in the industry discussion, and O'Reilly's warning deserves verbatim translation: when one agent writes code, another reviews, and a third adjudicates, you get **a closed loop of models with largely correlated blind spots** — especially when they come from the same model family, they will reach the same wrong consensus in the same places, with the same confidence.

Codex's architecture is precisely a response to this. Note two details in the Guardian system: reviewers have lifecycles (rotation), and there's a circuit breaker. **The institution's designers never assumed the reviewer is always right.** Reviewers get replaced, get cut off, rejections get ledgered — the existence of these mechanisms is itself an admission of, and contingency plan for, "AI-reviewing-AI may fail systematically."

Practitioner data backs this up. One developer's six-month retrospective on agentic code review: at initial deployment the false-positive rate was absurd — about 30% of review comments were hallucinations, citing functions that don't exist, suggesting changes that would break downstream services. **Sorting agent comments took more time than human review had; net productivity was negative.** After months of iteration, the working fixes were: confidence-filtering review comments (cutting noise by ~60%), feeding the reviewer system-architecture context (understanding "why it's designed this way" sharply improved review quality), and deliberately choosing a second model from a *different* family than the coding agent for independent review — again, to break correlated blind spots.

Put the practitioner fixes next to Codex's institutions and you see they're working two faces of the same problem: **practitioners tune the quality of a single reviewer; platforms build the constraints of a review system.** Confidence filtering corresponds to assessment parsing (making conclusions triage-able); cross-model review corresponds to reviewer lifecycle (making reviewers rotatable); circuit breaking and denial bookkeeping are backstops only a platform can provide.

In other words, the mature story is not the PR narrative of "AI guaranteeing AI quality." It's this: **AI-reviewing-AI can be an efficiency amplifier, but only when institutions bind it — rotatable, breakable, auditable — with human review channels and hard guardrails always kept underneath.**

## The arithmetic: output accelerating, review falling behind

The longer and more autonomously agents work, the harsher this arithmetic gets: generation throughput climbs every week, and review throughput is still human speed.

The loudest cross-project signal this week was a "correctness campaign": OpenClaw converging resource usage, Hermes sealing cron-scheduling edge conditions (early triggers, manual triggers, clock drift, future-instance pollution each fixed), Reasonix rewriting its session turn authority model. Head platforms are collectively entering the "still correct after running for seven days" phase.

The longer and more autonomously agents work, the less possible it is for humans to watch every line of output — and the less optional automated, institutionalized review becomes. The industry narrative has already drawn this move: Anthropic's agentic coding trends report lists "long-running autonomous agent teams" as a core prediction, with the engineer's role explicitly reframed toward "orchestration, quality assessment, and strategic decomposition." Review automation is the first hard bone on the "quality assessment" line of that role transition.

It's simple arithmetic: when review throughput can't keep up with generation throughput, you either automate review or you run naked on quality.

AllClaws' weekly report flagged "agent reviews agent" as a new signal beyond the established emerging paradigms and recommended it for the Q4-8 watchlist. Judging by this week's density — Codex institutionalizing it, OpenClaw closing the loop, industry discussion heating up — it's likely the next architecture pattern everyone copies.

## Four questions to ask any platform you're evaluating

**① Is the review stage pluggable or hardcoded?** Ask whether code review / self-check is an extension architecture or baked into the prompt. The former means review capability can evolve and be replaced independently — Guardian's eight commits all landed inside one extension; the main loop didn't move a line.

**② Do denials get ledgered? Does the reviewer have a circuit breaker?** "Denial accounting" and "circuit breaker" are terms you can throw verbatim. Without the ledger you can't say what review caught; without the breaker the AI review stage is itself a single point of failure.

**③ At what granularity is the human review channel?** Session-level, team-level, or tool-level? HiClaw sinking approvals to team scope shows "who signs off" is becoming a formal dimension of permission systems. Too coarse, and human review is either a rubber stamp or a bottleneck.

**④ What holds when nobody's watching?** In unattended mode, is it a hard allowlist or "trust the model's judgment"? Hermes' pattern-key allowlist plus invariant tests is the reference answer: institutions don't live in docs, they live in assertions.

The first half of the race was about whether agents can finish the work. This week the finish line visibly moved to: **the work the agent did — do you dare merge it without looking?** Whoever completes the review layer holds the actual ticket to the long-running-task game.

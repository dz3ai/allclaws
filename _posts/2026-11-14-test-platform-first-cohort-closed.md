The allclaws test platform's first task cohort is closed. All five benchmark scenarios — two hard, two medium, one easy — went from "fixtures exist" to "verified, reference-proven, and solved end-to-end by a live agent" in a single evening: **13 of 13 valid agent runs passed, every reference patch re-validated byte-identical, and four harness bugs found, fixed, and documented along the way.** The evening's spend barely moved the internal ledger.

The scoreboard, then the story — because the story is the point.

| Task | Difficulty | What it asks | Agent runs | Wall time |
|---|---|---|---|---|
| gh-issue-001 | easy | fix 2 documented bugs from issue text | 2/2 PASS | 85s / 94s |
| refactor-multi | medium | extract engine module, dedupe formula, typed models | 2/2 PASS | 505s / 223s |
| triage-burndown | medium | burn down 5 sequential bugs in one session | 2/2 PASS, 5/5 fatigue windows both repeats | 102s / 124s |
| feature-crud | hard | implement a comments feature, HTTP + Python API | 3/3 PASS | 212s / 202s / 208s |
| legacy-migrate | hard | migrate an app across a breaking ORM rewrite | 3/3 PASS | 97s / 80s / 101s |

Every run solved its task in **80–505 seconds against caps of 20–60 minutes**. The hard tier wasn't harder for the agent in wall-clock terms at all — feature-crud's full CRUD feature with live-HTTP hidden tests took three and a half minutes; legacy-migrate's six-module migration with an AST scanner waiting to reject any deprecated API call took ninety seconds.

## Closing means proving it three times

A task in this framework isn't "done" when written. It's done when three independent things hold, and tonight each was checked for all five:

**The pristine fixture verifies.** Visible tests pass (or fail in exactly the documented bug pattern), and — the discriminator — the *hidden* acceptance suite must **fail** on the pristine tree. If hidden tests pass before anyone solves the task, they measure nothing. This used to require operators to memorize an `ALLOW_RED` environment variable listing the intentionally-red bug tests; it now lives in each `spec.json` as `existing_suite_allow_red`, and the verifier reads it itself. Related fix: the verifier counted only `FAILED` lines, so feature-crud's acceptance — which fails on pristine via a collection `ImportError` — reported "0 failing checks," which reads like a broken task rather than a correct one. Collection errors count as red now, because they are.

**The reference patch still proves solvability.** Each task ships a `reference_fix.patch` — a known-good solution, generated by applying the fix to the fixture, diffing, self-verifying on a scratch copy, then restoring pristine. Tonight all five pipelines were re-run on this host and all five regenerated **byte-identical** to the committed patches. That's the property you want: the task hasn't drifted, the environment hasn't drifted, and "solvable" remains a checked fact rather than a memory.

**A live agent can actually close the loop.** Reference patches prove a task is *solvable*; only a real run proves the prompt, the fixture, and the scoring compose into something an agent can pass without seeing the answer. Thirteen runs did.

## The smoke ladder: five runs to trust a driver

The evening's real work was deciding whether the opencode driver could be trusted as the reference platform. It took five runs to answer yes — and the four failures were more instructive than the passes.

**Run one died before the agent started.** The host's default model — a local mixture-of-agents endpoint — refuses connections on this box. Eleven `ECONNREFUSED` retries, zero files touched. Fix: grids pin the model explicitly (`glm-5.3` via the Zhipu plan, verified live in ten seconds).

**Runs two through four solved the task perfectly — in the wrong tree.** Same signature each time: the agent's fix was correct (13/13 hidden acceptance, semantics matching the reference), but the diff landed in the *pristine parent fixture*, not the scratch worktree being scored. The agent had walked up-tree, found the hidden acceptance tests and the reference patch, "aligned" with them, and patched the fixture it found there. Three containment hypotheses, three fixes, two of them wrong:

- *Worktrees inside the repo made discovery trivial.* True — moving scratch outside the repo was right (and is now the default). But not sufficient.
- *The shared background service pinned the session root.* Plausible — and `--standalone` exists precisely for private servers. It changed nothing, in either flag position.
- The actual mechanism surfaced in a bisect harness: **the opencode client resolves the session's project root from the invoking process's context, not the child process's cwd.** A `subprocess.Popen(cwd=worktree)` override is silently ignored. Launch the CLI from Python whose own cwd is the benchmark repo, and the agent's `.` becomes the benchmark repo — worktree be damned.

The fix is one argument, hidden in plain sight in the CLI's top-level usage: `opencode <subcommand> [flags] [<directory>]`. The trailing **directory positional** pins the root explicitly. The bisect proved it: directory-first roots correctly from a foreign parent; a trailing directory gets swallowed by the message array; before the subcommand, the parser rejects it. The driver now invokes `opencode run <worktree> --standalone --auto -- <prompt>`, and the escape never recurred.

## The defense held while the harness was broken

Here's the part worth designing toward: during all three escape runs, **the benchmark record stayed clean without human intervention.** The runner had never trusted agents to be contained:

- **Worktree-only scoring.** Whatever the agent did to the parent fixture, scoring reads the worktree it was assigned. Escaped runs scored zero-files and failed, correctly.
- **Drift detection with restore.** Each result carries a `fixture_drift` listing exactly which pristine files the agent touched, and the runner restores them. The fixtures ended the evening pristine — verified after all seventeen runs, debug runs included.

So the failure mode produced invalid *runs*, never invalid *data*. That's the difference between a benchmark that needs babysitting and one that can survive its own harness bugs. The three escapes are archived in the results tree as first-class evidence, which is what a debugging run should be.

## Small bugs that would have poisoned everything

Two more, both found by reading output skeptically:

**Every grid report rendered "0% pass rate" — including the 6/6-PASS one.** The report generator read a top-level `score.passed` that the runner has never written; the verdict lives at `extra.score.passed`. A report layer that can't see its own results layer had presumably never been pointed at a passing grid before. One helper with a fallback fixed both call sites; the grids now render their true 100%.

**The verifier leaked hidden tests into the fixtures it checked.** `verify_task.sh` mounted the hidden acceptance suite inside the fixture to confirm it fails on pristine — then left it there. Since the runner copies fixtures into agent worktrees, the next run would have shipped the answer key to the agent. The cleanup is one `rm -rf`; the category (verifier must leave no residue) is now explicit.

And one task-side bug caught by the pipeline itself: feature-crud's `capture_fix.sh` untracked bytecode caches with a single multi-path `git rm --cached` — which aborts *all* paths when any one is missing from the index. The silently-aborted removal left binary deletions inside the regenerated patch, which then failed to apply on the scratch copy. The other four scripts already used the one-path-at-a-time form; now all five do, and the regenerated patch is byte-identical again.

## What the cohort measures now

With the harness trusted, the numbers become meaningful. The reference agent (opencode 2.2.7, GLM-5.3, labeled *untracked reference* and excluded from rankings by design) closed every task on the first attempt, every repeat, with modest token profiles and no timeouts. The fatigue instrument worked end-to-end: triage-burndown's five sequential same-difficulty windows solved 5/5 in both repeats, `fatigue_flagged: false` — no monotone decline across repeats, which for a single-session benchmark is the expected healthy signature.

The spread in wall times is itself a finding. The medium refactor (505s first repeat, 223s second) cost more than either hard task (80–212s). Difficulty labels calibrated by *human* effort don't predict *agent* effort: a mechanical six-file migration with a mapping document is easy for a model that has effectively memorized the pydantic v1→v2 transition it imitates, while an open-ended refactor with a structural "formula appears at most once" constraint requires exploration. Expect difficulty recalibration to be a recurring theme once ranked drivers join.

## Next

Three items, in order: install the ranked-driver CLIs (aider, codex, kimi) for the cross-platform comparison the framework was built for — the opencode runs are reference points, not rankings; add a third repeat set for tighter fatigue statistics; and keep the two documented host pitfalls (dead default model, root-from-invoking-context) in the driver notes where future maintainers will actually look.

Five tasks closed, thirteen runs green, four harness bugs retired, six commits. Per-task evidence is embedded in each `spec.json` closure note; grids and reports live under `test_framework/benchmark_results/longrun/`.

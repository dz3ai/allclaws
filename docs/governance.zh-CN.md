**[English](governance.md)** | 中文

> 与 ROADMAP Q4-7（类别覆盖缺口闭合）及平台评估标准配套。

## 为什么现在需要治理

AllClaws 跟踪 4 大类别的 34 个平台，外加 `architecture/agent_harnesses.md` 中的 7 个 harness 生态。2026 年 8 月覆盖审计排入了 8 个候选（Q4-7），同时 5 个已跟踪平台躺在停滞队列里。没有显式规则，每次准入和归档都是临时判断——20 个平台时还行，34+ 时不可持续。

本文档裁决 Q4-6 的四个研究问题：平台上限、准入标准、停滞处理、最小可行分析。

---

## 1. 上限裁决：35 个正式平台

**裁决：35 平台上限仅适用于正式平台跟踪（下文 Tier 1）**。它是质量预算，不是研究本身的增长限制。

理由：

- 14 文件准入 checklist（config.json + 对比文档 + README/MISSION/ROADMAP/LATEST_UPDATES 双语）每平台耗费整个工作会话，且制造永久性同步债务。每次新增还扩张 5 个对比矩阵。超过约 35 个后，单平台注意力将低于 AllClaws 的发布质量线。
- 上限**不**约束 Tier 2（harness 生态，单一架构文档内的轻量章节）或 Tier 3（观察名单，一行表格）。研究广度通过层级延续，不靠 Tier 1 通胀。
- Tier 1 满员时，新准入要求对等归档（见 §5）——目录变成可替换的，不是冻结的。

现状：34/35 个 Tier-1 名额已用。余 1 席。

## 2. 三档跟踪层级

「跟踪/不跟踪」的二分法退役。三档层级、三档义务：

| 层级 | 是什么 | 在哪里 | 义务 | 上限 |
|------|--------|--------|------|------|
| **Tier 1 — 正式平台** | 有本地检出和基准集成的独立 agent 平台 | `config.json` + submodule + 完整架构条目 + 5 矩阵 + 全部概览文档（14 文件，EN+ZH） | 月度更新周期；尽可能覆盖基准测试 | **35** |
| **Tier 2 — 生态跟踪** | 值得结构化分析但不需要完整基础设施的 harness/工具链生态和类别代表 | 相关 `architecture/` 文档中的一个章节（如 `agent_harnesses.md`），带 AllClaws 相关性说明；计入 MISSION 范围列表 | 至少季度复审；实质变化时更新 | 软上限（15 个时复审） |
| **Tier 3 — 观察名单（MONITOR）** | 当前未过硬标准（太新、rc 状态、轨迹不明）但架构意义重大的候选 | `docs/governance.md` §7 表格一行 + 状态变化时 LATEST_UPDATES 一行 | 每季度重估；2 个周期内晋升或除名 | 无 |

晋升路径：Tier 3 → Tier 2 → Tier 1，每步需满足 §3 标准。降级：Tier 1 → 归档（§5），或 Tier 1 → Tier 2（相关性缩小但保留历史价值的平台）。

**类别覆盖规则**：Tier 1 准入按类别缺口排序，不按星标数。代表未跟踪类别的候选（按 Q4-7 矩阵）优先于已覆盖类别中星标更高的候选。

## 3. 准入标准（正式化）

将 2026-07-06 与 2026-07-28 两批评估沉淀的标准正式化。五个维度：

| 维度 | 权重 | 标准 |
|------|------|------|
| 架构独特性 | **高** | 已跟踪平台未覆盖的新模式（按类别覆盖矩阵判断） |
| 活跃开发 | **高** | 最近 30 天内有提交且持续——非爆发后沉默（核查 90 天轨迹） |
| 形式因子 | **高** | 有独立 agent 运行时的独立平台/CLI/框架。非 IDE 扩展、插件层、agent 舰队管理器或单薄 LLM SDK 封装 |
| 社区引力 | 中 | 真实星标/fork/贡献者（非 bot 刷）；无最低门槛——有新模式的 189 星平台（Maxclaw）优先于休眠的 69K 星平台（MetaGPT） |
| 许可 | 中 | 偏好 MIT/Apache-2.0；自定义或 NOASSERTION 许可需在条目中显式标注 |

**决策矩阵：**

- **TRACK**（按形态入 Tier 1 或 2）：满足全部三个高权重标准，且填补类别缺口或代表真正的新模式
- **TIER-2**：满足高权重标准但是 harness/工具链/子系统（非完整平台），或达标但 Tier 1 已满员
- **MONITOR**（Tier 3）：架构意义重大但当前一项硬标准不达标——创建不足 1 个月、pre-1.0 rc 且声明破坏性变更、或无 90 天持续活动证据。季度重估
- **SKIP**：形式因子不符、休眠、红旗

**红旗（自动 SKIP，沿用 7 月标准）**：混淆 JS 载荷；bot 刷 commit；无真实代码（<200KB 营销壳）；自称「方法论而非平台」；VS Code/IDE 扩展形态；休眠后诈尸式重写的活动模式。

**已立案的反转判例**：低代码拒绝标准于 2026 年 7 月收窄——带完整 agent 运行时 + 工具调用的可视化平台（Dify）不只是流程设计器。个人助手、扩展层、舰队管理器、领域专属非 agent 工具仍排除。

## 4. 最小可行平台分析

14 文件 checklist 是 Tier-1 标准。任何层级条目的**最小可行分析**为：

1. **分类行**——语言、规模、类别
2. **哲学**——一句话可靠性押注（出自 harness 对比的哲学图谱）
3. **架构事实**——入口、模式、关键模块、MCP 状态、部署、数据库、安全（platform_comparison 字段集）
4. **AllClaws 相关性**——为什么跟踪它；它回答哪个研究问题
5. **一个已验证数据点**——至少一个写作时对照来源核实的数字（星标、LOC、基准指标、发布节奏）

缺 #4 或 #5 的条目是占位符，不是分析。Tier-2 章节必须在其架构文档章节内满足同样最小标准。

## 5. 停滞与归档

**停滞定义**：6 个月以上无提交。季度复审（§6）把停滞平台推向决策，而非自动归档。

**归档标准——须全部满足：**

1. 停滞（6 个月无提交），且
2. 无战略意义（非参考实现、非某跟踪类别的唯一代表、未被 2+ 份研究报告引为证据），且
3. 无待决 roadmap 相关性（非开放研究项的输入）

**归档机制**：移除 submodule + config.json + 矩阵 + 文档章节（12 文件移除 checklist）；平台条目移入 `platform_comparison.md` 历史附录并注明归档原因；研究报告不动（它们是历史产物）。归档释放一个 Tier-1 名额。

**降级替代**：有历史意义的停滞平台降级为 Tier 2（架构文档保留章节，移除基础设施），而非完全归档。

## 6. 季度复审流程

**触发**：每个季度月（1/4/7/10 月）第一个星期一，搭载月度生态报告周期。

**流程（单次会话，checklist 驱动）**：

1. **停滞清扫**——`git submodule status` + 各平台 `git log -1` 日期；标记所有 ≥6 个月停滞项
2. **观察名单清扫**——重估每个 Tier-3 条目：晋升（标准已满足）、保留（一行理由）或除名（2 周期已过）
3. **Tier-2 清扫**——检查各生态章节是否过时；更新或标注
4. **名额核算**——Tier-1 数量 vs 上限；满员且有候选待入时，决定归档/降级释放名额
5. **产出**——`docs/PROJECT_STATUS.md` 中一段带日期的记录 + 本文档表格更新；commit 引用本文档

**时间预算**：清扫本身是机械操作（用 drift-check 脚本约 30 分钟）；决策是唯一的判断环节。

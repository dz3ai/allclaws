# ClawTeam Profile and Identity Analysis

ClawTeam does not implement user profiles in the traditional sense (authentication, multi-tenant identity). Instead, identity manifests through TOML-based team templates that define per-team agent configurations. According to architecture_comparison.md, "Team templates (TOML-based team definitions)" specify agent roles, tasks, and coordination patterns for each project. Identity is team-scoped rather than user-scoped—a `fund1` template defines analyst and portfolio manager agents, but does not distinguish which human user created the team.

Agents are identified through TOML team definitions and CLI spawning. Each agent in a team receives a role (e.g., "backend engineer", "frontend developer") specified in the team template, and the leader tracks agent status through the centralized task system. platform_comparison.md documents that "Per-agent model assignment" allows different agents to use different models within the same team—a preview feature enabling model resolution across heterogeneous agents.

The agent model resolution chain provides 7-level priority for determining which model each agent uses: CLI argument > agent model setting > agent tier > template strategy > template model > config default > None. This chain, documented in multi_agent_coordination_research.md (ClawTeam v0.3.0 section), enables mixed-model teams where Claude, GPT, and Qwen models operate together under the same leader. Identity is thus bound to model configuration as much as agent role.

CLI agent integration extends identity to external tools. ClawTeam supports OpenClaw (native integration), Claude Code (full support), Codex (full support), nanobot (full support), Cursor (experimental), and custom scripts. Each backend agent brings its own identity and credential system—ClawTeam does not centralize these. When spawning a Claude Code agent, ClawTeam delegates to that tool's existing identity handling rather than implementing its own.

The key insight: ClawTeam treats identity as a team-level concern rather than user-level. TOML templates define agent roles and model assignments, the leader orchestrates these agents, and external CLIs contribute their own identities. For personal multi-agent workflows where the user is implicit, this model works. For multi-user systems requiring audit trails and per-user permissions (like GoClaw's RBAC or HiClaw's Worker CRDs), ClawTeam would need identity primitives beyond team templates.

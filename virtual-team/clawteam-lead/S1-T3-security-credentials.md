# ClawTeam Security and Credentials Analysis

ClawTeam's security model relies on agent isolation via git worktrees and file-based state with fcntl locking, but lacks enterprise-grade credential management features found in GoClaw or IronClaw. According to platform_comparison.md, security is achieved through "Agent isolation via git worktrees" rather than credential encryption or access control lists. Each agent operates in its own worktree with separate state files, preventing filesystem-level cross-contamination but providing no process-level credential isolation.

File-based state management uses fcntl locking for crash safety. As documented in architecture_comparison.md, all state persists as JSON files in `~/.clawteam/` (teams/, tasks/, inboxes/, workspaces/), with file locks preventing concurrent writes. This zero-config approach eliminates database dependencies but provides no encryption at rest—credentials stored in TOML team templates or agent configs are plaintext files on disk.

The trust model assumes agents are trusted subprocesses spawned by the user. ClawTeam supports multiple agent backends (OpenClaw, Claude Code, Codex, nanobot, Cursor), but treats each as a black box with its own credential handling. According to multi_agent_coordination_research.md, there is no centralized secret injection mechanism like GoClaw's AES-256-GCM encryption or IronClaw's host-boundary credential injection. Each agent must manage its own API keys, typically through environment variables or config files within its worktree.

Limitations for enterprise security are significant. governance_frameworks_analysis.md notes that credential isolation remains the hardest problem across all platforms, and ClawTeam's approach—file-based state without encryption, no RBAC, no audit logging—makes it unsuitable for regulated environments. The lack of multi-tenant isolation (unlike GoClaw's PostgreSQL workspaces) means all users share the same `~/.clawteam/` state directory, creating potential cross-user data exposure on shared systems.

The key assessment: ClawTeam prioritizes developer productivity over security hardening. Git worktree isolation prevents merge conflicts, fcntl locking ensures crash safety, and file-based state keeps things simple. For personal or small-team use cases where all agents run under the same user account, this is acceptable. For enterprise deployment requiring credential encryption, audit trails, and multi-tenant isolation, ClawTeam would require substantial security hardening.
